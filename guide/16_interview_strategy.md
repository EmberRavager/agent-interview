## 面试策略建议

### 先讲理解，再讲名词

**很多人失分，不是不会，而是回答像在“背文档”。**

推荐每题都尽量按这个顺序回答：

1. **先下自己的判断**
- 先给一句你真正理解后的结论，比如“我认为核心矛盾是控制力和速度的取舍”

2. **再解释为什么**
- 讲背后的机制、约束或工程原因，而不是只报名词

3. **再补工程取舍**
- 什么时候适合，什么时候不适合，代价是什么

4. **最后用项目或指标落地**
- 最好接一句“我在项目里就是这么处理的”

**一个通用模板：**

> 我的理解是……  
> 它本质上解决的是……  
> 真正难点不在……而在……  
> 如果放到工程里，我会优先关注……  
> 我之前项目里对应的做法是……

**反例：**
- “LangGraph 是图结构框架，CrewAI 是多角色框架，AutoGen 是微软的……”

**正例：**
- “我更关心框架给我多少流程控制权。因为一旦任务要重试、审计、恢复执行，纯对话式编排会很快失控，所以我上线场景更偏状态机。”

**判断标准：**
- 如果你的回答把产品名替换掉，逻辑还成立，说明你在讲原理
- 如果换个名词整段就垮了，说明大概率还是在背概念

### 回答框架（STAR-L）

```
Situation → Task → Action → Result → Learning
```

**示例：** 「在之前的 Agent 项目中，我们发现工具调用失败率达 18%（S）。我负责优化工具调用的可靠性（T）。我设计了 JSON Schema 校验 + 模糊解析 + 3 次重试的三层保障方案（A）。上线后失败率降至 0.4%（R）。这件事让我意识到 Agent 工程中，可靠性比智能更重要（L）。」

### 红线提醒

- 别说「我觉得效果挺好的」——所有结论必须**有数据支撑**
- 别只会调 LangChain API——要展示对**底层原理**的理解
- 别说「Agent 就是带工具的 Chatbot」——这是面试官最讨厌的回答
- 别夸大类 Agent 的自主性——强调 HITL 和安全兜底

### 准备清单

- [ ] 至少深入理解 1 个 Agent 框架（LangGraph / CrewAI / AutoGen）
- [ ] 有 1 个可展示的 Agent 项目（含数据、架构、效果）
- [ ] 手写过 ReAct Agent 的完整代码
- [ ] 了解 MCP 协议，能说清解决了什么问题
- [ ] 能讲清 Context Engineering 和 Prompt Engineering 的区别
- [ ] 准备 1 个关于幂等性 / 恢复 / 权限控制的工程案例
- [ ] 准备 3 个「你遇到的最大挑战」故事（按 STAR-L 结构）
- [ ] 能画出一个 Agent 系统的架构图

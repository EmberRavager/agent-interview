## 十四、2025-2026 前沿热点（10 题）

### 1. MCP（Model Context Protocol）如何改变 Agent 开发生态？

**核心判断：MCP 已不只是“工具调用格式”，而是在成为 Agent 基础设施协议。**

**MCP 三层架构：**

```
MCP Host (Claude Desktop / IDE / ChatGPT / Agent Runtime)
    ↓
MCP Client (协议层，处理通信)
    ↓
MCP Server (工具/资源提供方)
    ├── File System Server
    ├── Database Server
    ├── GitHub Server
    └── Custom Servers
```

**为什么重要：**
- 把“每接一个系统就写一次 adapter”变成“按协议接入”
- 不只暴露 `tools`，还能暴露 `resources`、`prompts`
- 让权限、授权、传输、审计这些工程问题有统一抽象
- 更适合作为 IDE Agent、企业 Copilot、Multi-Agent 平台的底层连接层

**标准回答示例：**

> 我会把 MCP 理解成 Agent 世界里的标准连接层，它真正改变的是集成方式，而不只是工具调用格式。过去是每接一个系统写一个 adapter，现在是尽量按协议接入。

### 2. DeepSeek R1 的「测试时缩放」是什么？

传统方法：加大训练数据 → 更大模型 → 更好效果。

**测试时缩放（Test-time Scaling）：**

- 推理时让模型生成更长的「思考链」
- 不是训练时增大参数，而是推理时增加计算
- DeepSeek R1 通过强化学习让模型自主学会长链推理

**Agent 启示：** 复杂规划任务可以分配更多推理 Token，简单任务快进快出。

**标准回答示例：**

> DeepSeek R1 这类测试时缩放的启发是，复杂任务不一定都要靠更大模型解决，也可以靠推理时分配更多计算。对 Agent 来说，这直接影响规划层如何分配思考预算。

### 3. OpenAI o1/o3 系列对 Agent 开发有什么影响？

- **内置推理能力**：不再需要手动写 CoT Prompt
- **推理时间换质量**：复杂任务自动延长推理
- **推理预算控制**：通过 `reasoning.effort` 等参数控制深度
- **工具链整合更强**：推理模型和工具调用结合时，要保留函数调用间的推理上下文，而不是每轮“清空重来”

**改变：** Agent 的 Planner 层可以大幅简化——把复杂推理交给 o1/o3，Agent 框架只负责工具编排。

**标准回答示例：**

> 这类推理模型的意义，不只是答题更强，而是让一部分原本要手工写在 Planner 里的推理，转移回模型本身。框架层的价值会更多落在编排和治理。

### 4. GraphRAG 是什么？相比传统 RAG 有什么优势？

**GraphRAG（微软 2024）：**

- 传统 RAG：检索孤立的文本块
- GraphRAG：建立实体/关系/社区的**知识图谱**，检索时返回主题摘要 + 关联实体

**优势：**
- 能回答需要全局理解的问题（如「这个数据集的主要主题是什么？」）
- 发现跨文档的隐含关联

**标准回答示例：**

> GraphRAG 的核心价值在于补足传统 chunk 检索对全局关系理解不足的问题。它特别适合需要跨文档、跨实体推理的场景，但代价是构图和维护复杂度更高。

### 5. A2A（Agent-to-Agent Protocol）是什么？

Google 于 2025 年提出、后续捐赠给 Linux Foundation 的多 Agent 通信标准。

**与 MCP 的关系：**
- MCP：Agent ↔ 工具/资源的连接
- A2A：Agent ↔ Agent 的连接

**核心概念：**
- Agent Card：描述 Agent 能力和端点
- Task：标准化任务对象，包含任务状态与生命周期
- 支持流式、异步、多租户和企业级安全特性

**面试回答别只停在概念层：**
- A2A 的价值不只是“聊天”，而是**可委派、可追踪、可恢复**
- 一个 Agent 不需要暴露内部 Prompt、Memory、Tool 细节，只暴露能力边界和任务接口
- 所以它很适合跨团队、跨厂商、跨安全域协作

**标准回答示例：**

> 我理解 A2A 的意义在于把 Agent 之间的协作从私有协议变成标准化任务交互。它不是让 Agent 多说话，而是让委派、追踪和恢复这件事更可控。

### 6. Web Agents（浏览器自主操控）的最新进展？

**核心技术栈：**
- 视觉理解（截图 + DOM 树）
- 元素定位（视觉 + 可访问性树 + DOM/selector）
- Grounding（把自然语言目标稳定映射到页面元素）
- 操作模拟（点击、输入、滚动、拖拽、Tab 切换）
- 状态管理（多页面、多 Tab、登录态、权限弹窗）

**2026 面试更关注的点：**
- Web Agent 不是“会点网页”就行，难点在 `grounding + verification + safety`
- 必须做操作后二次验证，例如点击后校验 URL、DOM 变化、成功 toast、表单值
- 浏览器能力越强，越要强调权限边界、敏感操作确认和回放审计

**标准回答示例：**

> Web Agent 真正难的不是会不会点页面，而是定位准不准、验证做没做、权限怎么管。也就是说，grounding 和 safety 往往比“会操作”本身更重要。

### 7. Code Agent（如 Devin、Cursor Agent）的技术架构？

**核心能力链：**

```
理解需求 → 搜索代码库 → 读取相关文件 → 
生成修改方案 → 编写代码 → 运行测试 → 
修复错误 → 提交 PR
```

**关键组件：** 代码库索引（RAG on codebase）、LSP 集成、沙箱执行、Diff 生成与展示。

**标准回答示例：**

> Code Agent 的核心不是单轮补全，而是代码库理解、环境执行、测试验证和版本控制闭环。它更像一个小型软件工程系统，而不是更强的 IDE 插件。

### 8. Multi-Agent RL（MARL）在 Agent 协作中的进展。

**代表算法：**

| 算法 | 特点 |
|------|------|
| MADDPG | 集中训练-分布执行（CTDE） |
| QMIX | 单调值分解，保证全局最优 |
| MAPPO | 多 Agent PPO，简单有效 |

**落地挑战：** 非平稳性（每个 Agent 都在学习，环境对单个 Agent 来说不断变化）、信用分配（成功归功于哪个 Agent）。

**标准回答示例：**

> 多智能体强化学习在 Agent 协作里最有意思的点，是它试图把协作策略学出来，而不只是手写流程。难点也很明显，就是非平稳性和信用分配。

### 9. 合成数据闭环（Self-Improving Agents）的最新范式。

**自我进化循环：**

```
Agent 执行任务 → 收集执行轨迹 → 
自动筛选高质量轨迹 → 生成训练数据 → 
微调模型 → 重新部署 → 循环
```

**代表方法：**
- STaR（Self-Taught Reasoner）：正确轨迹直接训练，错误轨迹给正确答案后训练
- Quiet-STaR：在每个 token 位置并行生成推理，学习「什么时候该想」
- MCTS 数据合成：用搜索树生成多样化推理路径

**标准回答示例：**

> Self-Improving Agent 的关键不是“自动训练自己”听起来多酷，而是高质量轨迹筛选、评测和安全边界是否跟得上。否则它可能只是在自动放大错误。

### 10. 对未来 1-2 年 AI Agent 发展的判断。

**趋势预判（适合面试展示思考深度）：**

| 趋势 | 判断 |
|------|------|
| 推理能力的 Commoditization | o1/o3/R1 让复杂推理民主化，Agent 框架价值向编排层迁移 |
| MCP/A2A 标准化 | 工具互联互通成为事实标准，Agent 将从「写 adapter」变为「接协议」 |
| 个人 Agent 爆发 | 每个人有一个专属 Agent（日程、邮件、购物），类似 Jarvis |
| 安全合规成为门槛 | 监管趋严，Agent 安全从「加分项」变为「准入门槛」 |
| 成本持续下降 | Token 价格年降 80%+，Agent 从「奢侈品」变为「日用品」 |

**标准回答示例：**

> 如果让我总结未来 1-2 年，我会说推理能力会继续商品化，真正拉开差距的会是工具接入、上下文工程、治理能力和真实场景闭环。模型越来越强，但系统工程仍然是护城河。
